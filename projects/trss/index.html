INDEPENDENT NEURAL GRAPHICS RESEARCH / IN DEVELOPMENT

TrSS.

TrSS (Tamasrazim’s Real-time Scene Synthesis) is independent research exploring DLSS 5-style neural-rendering concepts for Intel Arc GPUs: reconstructing richer, temporally stable game frames from real-time graphics data, starting with an Intel Arc B580 target.

The long-term aim is a low-latency neural-rendering stage that complements a game’s existing renderer. DLSS 5 is a public reference for this research direction, not a dependency or an implementation being ported. The project has dataset tools, a trainable reconstruction baseline, offline evaluation and native graphics API experiments. It is not yet a plug-in, a finished live-game renderer, or a promise of instant photorealism.

The direction: neural rendering.

DLSS 5 is a useful public reference point for the wider field: neural rendering can be used as a graphics-pipeline stage to enhance a game frame’s apparent lighting and material detail.

REFERENCE / DLSS 5NVIDIA

3D-guided neural rendering

NVIDIA describes DLSS 5 as a neural-rendering stage grounded in the game’s rendered frame and engine-side information, designed to add lifelike lighting and material appearance while retaining the authored scene structure.

TRSS / INDEPENDENTINTEL ARC RESEARCH

A separate path—not a DLSS port

TrSS is an independent experiment with its own data, reconstruction model and inference work, aimed first at exploring an Intel Arc graphics path. It does not use NVIDIA’s proprietary DLSS 5 model and is not affiliated with NVIDIA.

Equivalent image quality, real-time performance and compatibility have not been demonstrated.

THE GOALNOT YET PROVEN

From sample frames to a real renderer

The intended result is a practical neural stage that could improve rendered game frames without breaking scene structure or temporal stability. Proving that requires representative captures, renderer data where available, controlled comparisons, and measured performance on real hardware.

What exists in the code.

Working components and automated tests are real progress, but they do not yet add up to a complete live neural renderer.

01 / MODELBASELINE

Trainable 2× reconstruction

The current first-party model is a frame-reconstruction baseline with a simple temporal blend. Photorealistic quality has not been demonstrated.

02 / DATAPIPELINE

Generate and audit datasets

Includes deterministic synthetic scenes, scene-separated train/validation splits, provenance checks, review galleries, and import paths for recorded RGB footage.

03 / EVALUATIONOFFLINE

Measure against a baseline

Checkpoint evaluation reports MAE, RMSE and PSNR against bicubic interpolation and creates side-by-side comparisons using held-out frames.

04 / CAPTUREWINDOWS

Collect game images locally

Windows capture tools collect visible color samples without modifying game processes. The recorder adds game-library detection, a 120-second warm-up and 23 MiB JSON chunks.

05 / GRAPHICS APIPROBES

D3D9 / D3D11 / D3D12

Native smoke tests exercise selected device, compute, fence, render-target and readback paths. These are API experiments, not game injection or renderer validation.

06 / GPUEXPERIMENTAL

Intel Arc research path

Device discovery and experimental Vulkan/XMX work are in the repository, but no complete live-rendering result has been validated on a physical Arc B580.

What remains.

The hard parts stay visible rather than being hidden behind a progress badge.

OPEN / 01REAL INPUTS

Renderer-specific access

A proper integration needs real render targets, depth, motion vectors, camera state and temporal history. The current RGB recorder cannot supply those buffers.

OPEN / 02TRAINING DATA

Representative captures

Collect permitted game samples, train with session-separated validation, and test whether the model improves visual results beyond a simple baseline.

OPEN / 03HARDWARE

Arc B580 validation

Measure image quality, latency, stability and memory use end-to-end on the physical target GPU. No verified live-game performance numbers are claimed here.

Research build—not a plug-and-play graphics feature.

There is no validated live-game neural renderer or completed Arc B580 performance test yet. Capture, offline training and native probes remain separate parts of the work.
