How TRILYVA works

TRILYVA uses the browser's real media and encoding support. Available exports depend on your browser and the settings it can handle.

01 / CODE

Write the motion, not every keyframe

Animations are driven by code and reusable logic, which makes it easier to describe a pattern than to place every frame by hand.

02 / PREVIEW

Preview performance is separate from export

At demanding resolutions, frame rates, or bitrates, the live preview may lag as your system works harder. Preview stutter affects responsiveness; it does not determine the final export's frame sequence.

03 / RENDER

Every requested frame is rendered individually

TRILYVA exports from the requested frame sequence rather than recording the live preview in real time. The exporter processes frames by index and verifies the resulting sample count; preview lag alone does not cause frames to be skipped in the final export. If verification detects a mismatch, the output is not marked as valid.

04 / OUTPUT CAPABILITIES

Up to 16K, 240 fps and 2 Gbps

TRILYVA provides settings for output up to 16K resolution, 240 frames per second, and a target bitrate of 2,000 Mbps (2 Gbps). These are upper configuration limits, not a guarantee that every combination will encode on every device. Actual availability depends on browser and codec support, hardware, memory, and operating-system limits.

05 / VIDEO

Use an export path the browser supports

Encoding and container output are handled separately. H.264/AVC and VP8/VP9 paths are offered when the browser supports them.

06 / AUDIO

Offline Voice Studio

I also built an offline voice studio using formant synthesis. It can produce timed dialogue, a procedural soundscape, a five-minute PCM WAV and subtitle cues; the voice is intentionally synthetic, not a neural voice clone.

07 / MOVIE

Local Movie Finalizer

The local finalizer combines a video or stock clip with a browser-decodable audio file. MP4 depends on recorder support; automatic mode can fall back to WebM. It captures and re-encodes in real time, so this isn't a lossless muxer.

08 / VECTOR

Creative export workflows

TRILYVA sits alongside my vector tools and stock-asset workflow, but those tools keep their own pages and workspaces.

09 / LIBRARY

Render a complete library

Choose a built-in or imported JavaScript library, then export the collection into a folder or ZIP. Each item receives its own video, selected still frames, and metadata files.

10 / STILL FRAMES

18 still-frame image formats

The Inspect Frame → Save this frame as picker exports PNG, JPEG, WebP, AVIF, BMP, TIFF, GIF, ICO, TGA, QOI, SVG, EPS, PPM, PGM, PBM, PAM, XBM and XPM. WebP/AVIF depend on browser encoder support; inspector SVG/EPS contain raster image data. The separate Render panel and library-batch still export offers PNG, JPG, SVG and EPS.

11 / INSTALL

Browser-first delivery

Open the renderer in a supported browser. Export options vary by browser and hardware, and folder/ZIP destination pickers require compatible browser support.

12 / SOURCE FILES

Save a project or just the JavaScript

ANIMATION SOURCE → Save opens a format picker. Choose .tmotion for source plus composition/settings, or .js for the animation source only. The editor also uses syntax colours to help distinguish language structures, values, functions, and renderer APIs.

13 / LIBRARY DOWNLOADS

Download one animation or a whole source library

The Library tab can download one selected animation as .js or package a selected library into a ZIP with library-manifest.json and README.txt. This source-download path is separate from rendering library videos and still frames.

Complete capability index

A practical reference to the current browser workspace. These are the features implemented in the browser renderer; operating-system, memory, browser encoder, and file-picker capabilities still set the real limits.

AUTHORING / JAVASCRIPT

Code-driven animation

Write a complete animation using window.renderFrame(time, frame, fps, ctx, width, height). The editor includes syntax colours, find/replace, reindent, undo/redo, source analysis, paste, copy, clear, examples, and a copyable animation prompt. The renderer supplies a Canvas 2D context and composition dimensions.

COMPOSITION / TIME

Control the frame model

Choose standard sizes from 720p through a 16K preset, custom dimensions up to 16,384 pixels per side, preset frame rates up to 240 fps, a custom rate from 1 to 240 fps, and durations from 0.05 seconds up to one hour. Configure background colour/opacity, a random seed, looping, loop duration, retiming, and reverse playback.

PREVIEW / TIMELINE

Inspect motion precisely

Use the centered playback bar for first frame, previous frame, play/pause, next frame, last frame, and loop. Adjust displayed preview scale with the scale slider and FIT button, set preview playback speed from 0.25× to 4×, scrub the timeline, inspect an exact frame, compare preview with the export path, and open fullscreen. Preview playback speed does not change final render FPS.

RENDER / VALIDATION

Render and verify

Analyse a job, run a test render, choose Draft/Standard/High/Maximum quality, configure a target bitrate up to 2,000 Mbps (2 Gbps), view browser encoder diagnostics, and enable or disable frame fingerprints. Compatible browsers may provide MP4/H.264 or WebM/VP8/VP9 output. Sample counts and completed containers are checked; unsupported codec/settings combinations are not guaranteed.

PROJECT / METADATA

Save work and identify output

Save projects in browser storage, open or duplicate projects, import/export the .tmotion project package, and download the animation as .js. Metadata fields cover project name, creator, composition, description and language; the source panel reports line count and SHA-256, and the metadata panel can copy a JSON receipt.

LIBRARY / BATCH DELIVERY

Manage animation collections

Use built-in libraries or import JavaScript files, folders of JS files, or ZIP collections as separate local libraries in the current browser. Download one animation as JS or a whole source library as ZIP with a manifest and README. Render a complete library to a folder or ZIP with per-animation media and metadata; browser file-system support is required for folder destinations.

FRAME INTELLIGENCE

Inspect and classify a frame

Inspect the actual rendered frame at composition size, check pixel-level information, and use the built-in heuristic frame-intelligence workflow to suggest stock-oriented categories and keywords. Keyword suggestions are assistive and should be reviewed before use as factual metadata.

RELATED MEDIA WORKFLOWS

Keep tool scopes distinct

The project overview also describes a local movie finalizer and an offline synthetic-voice tool. Those workflows have their own constraints; they are not interchangeable with the deterministic frame exporter, and real-time finalisation can behave differently under load.

All 18 inspected-frame image formats

Use Inspect Frame → Save this frame as. WebP and AVIF rely on the browser's canvas encoder. The inspector's SVG embeds a PNG and its EPS stores raster image data, so those two are wrappers rather than editable vector paths. Standard render and full-library batch settings have a separate four-format selection: PNG, JPG, SVG and EPS.

Frame model

The preview can prioritise responsive playback. Export follows the requested frame sequence instead.

TIMEBASE

time = frame / fps

Every output frame has a position in the requested timeline. Rendering slowly should not change where that frame belongs.

SEPARATION

A preview is not a render

Playback can skip ahead to stay interactive; offline rendering works through the requested frames one by one.
