Workspace capabilities

The renderer uses browser capabilities and actual supported export paths. The list describes the workspace architecture; support depends on the current browser and chosen configuration.

01 / CODE

Write procedural motion

Create motion through code and reusable procedural logic rather than relying only on a timeline of hand-placed elements.

02 / PREVIEW

Explicit frame clock

Preview and export are separate. The export clock derives from frame index and FPS, so slow rendering does not silently skip requested frames.

03 / RENDER

Browser capability checks

Before rendering, the workspace probes available codec/resolution/FPS combinations and avoids pretending unsupported settings work.

04 / VIDEO

MP4 and WebM paths

The media stack separates encoding from container output, with browser-based H.264/AVC and VP8/VP9 paths when supported.

05 / VECTOR

Creative export workflows

The larger TRILYVA project family includes vector-oriented and stock-asset tooling alongside procedural animation workflows.

06 / INSTALL

Browser-first delivery

Open the workspace directly in a supported browser. Export formats are conditional on browser features; the project does not claim every codec/device combination will work.

Frame model

The key distinction is between how fast the preview plays and which frames are requested for an export.

TIMEBASE

time = frame / fps

The output clock is derived from a specific frame index and requested frame rate, so a render can take longer without changing the target time of a frame.

SEPARATION

Preview ≠ export

Interactive playback can prioritise responsiveness while offline rendering still iterates across requested frames deterministically.

VALIDATION

Honest capability checks

Resolution and frame rate must be checked against browser/device encoder support before the app enables the export route.
