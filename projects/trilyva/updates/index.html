DIAGNOSTICS / GPUADDED

Live GPU backend diagnostics

The Diagnostics tab now separates browser WebGPU support from actual rendering activity. It reports whether a WGSL shader is declared, whether the automatic Canvas 2D compatibility route is available or active, whether a GPU device has been initialized, and which backend produced the latest frame.

  • The Re-check action queries the render worker for its current GPU state instead of relying only on cached interface values.
  • Unsupported Canvas 2D operations, vector-edit overlays, unavailable GPU helpers, and failed GPU initialization are reported as explicit fallback reasons.
  • The main-thread fallback is identified as native Canvas 2D; browser WebGPU support alone is never presented as proof of GPU rendering.
WORKER-OWNED STATUS / LIVE RE-CHECK / HONEST FALLBACK REPORTING
20 Nov 2026Recent engineering
GPU / RENDEREREXPERIMENTAL

Automatic GPU path for compatible Canvas 2D frames

TRILYVA can now record a supported subset of ordinary Canvas 2D drawing commands and submit those primitives to WebGPU. The original JavaScript renderFrame() contract remains in place.

  • Supported primitives include rectangles, circles and arcs, line paths, convex filled paths, common solid colours, alpha, save/restore, and affine transforms.
  • Unsupported APIs stay on the native Canvas 2D renderer. This is a partial compatibility layer, not a universal JavaScript-to-GPU compiler.
  • The compatibility path is attempted for preview, still-frame inspection, and frame export when WebGPU is available.
FALLBACK PRESERVED / NO AUTOMATIC RESOLUTION REDUCTION

GPU / EXPORTEXPERIMENTAL

Direct GPU preview and video-frame handoff

Compatible GPU-only compositions can bypass intermediate Canvas 2D staging. Where the browser accepts a WebGPU canvas as a video-frame source, the export path can create timestamped frames directly from that surface.

  • The direct path is restricted to compositions without visible media layers or vector-edit overlays.
  • When the browser rejects the direct video-frame source, TRILYVA snapshots the already-rendered GPU surface and uses the regular composition path.
  • Mixed compositions keep the normal compositor so backgrounds, media transforms, blend modes, and vector overlays remain intact.

GPU / RENDEREREXPERIMENTAL FOUNDATION

First WebGPU frame-rendering backend

A worker-based WebGPU renderer was added alongside the existing deterministic frame pipeline. Animation sources can provide WGSL shader code for fragment or compute rendering while keeping GPU objects inside the dedicated render worker.

  • Fragment mode for fullscreen shader rendering and compute mode for per-pixel parallel workloads.
  • Frame uniforms carry time, frame index, FPS, dimensions, duration, loop state, speed, and related render parameters.
  • A deterministic WebGPU stress scene, diagnostics, service-worker assets, and renderer contract tests were added with the backend.

VIDEO EXPORTGUARDRAILS ADDED

Movie Finalizer bitrate and file-size limits

The local video finalization flow gained a minimum video bitrate of 20 Mbps and a strict 2 GB output-file cap. The default quality target is 25 Mbps. When the estimated output exceeds the cap, TRILYVA warns before proceeding; it does not silently lower bitrate, resolution, or visual quality to force the file under the limit.

LOCAL FINALIZATION WORKFLOW

GPU status, honestly

GPU rendering is real code in the browser renderer, but it is not a promise that every animation now runs entirely on the GPU.

What can use WebGPU

  • Animation sources that provide a compatible WGSL descriptor can use the fragment or compute renderer.
  • A supported subset of Canvas 2D primitives can be converted to GPU draw commands automatically.
  • Eligible GPU-only compositions can use direct preview and video-frame paths, subject to runtime browser capabilities.

What still falls back

Text, images and patterns, gradients, shadows, filters, clipping, non-source-over blend modes, path holes, and other unsupported Canvas 2D APIs continue through the native Canvas 2D path. Mixed media and vector-edit compositions also retain the regular compositor.

WebGPU availability and performance depend on the browser, operating system, driver, adapter, and requested render dimensions. TRILYVA does not gain native-level hardware control or guaranteed multi-GPU rendering through the browser.
