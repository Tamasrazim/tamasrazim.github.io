02 / FIRST ANIMATION

Paste this exact starter.

This is the same basic renderFrame() pattern documented in the live workspace's Quick Start.

window.renderFrame = function (time, frame, fps, ctx, width, height) {
  ctx.fillStyle = "#000";
  ctx.fillRect(0, 0, width, height);
  var x = width * 0.5 + Math.cos(time * 2) * 200;
  ctx.fillStyle = "#fff";
  ctx.beginPath();
  ctx.arc(x, height * 0.5, 40, 0, Math.PI * 2);
  ctx.fill();
};
01

Open the workspace

Open TRILYVA, find the Animation Source editor, and select the existing example code. Save a copy first if you want to keep the current project.

02

Replace and run

Paste the starter function and press Run (Ctrl + Enter on Windows/Linux, or ⌘ + Enter on macOS). You should see a white circle moving horizontally on black.

03

Scrub to test

Move the timeline or step frame-by-frame. The circle's position is derived from time, so jumping directly to a frame still gives the correct position.

TRILYVA's full render function contract is renderFrame(time, frame, fps, ctx, width, height). You can declare fewer arguments if you do not need them. Do not create your own canvas or call requestAnimationFrame() inside the animation.
03 / FRAME MODEL

Think in frames, not wall time.

FRAME TIME

One formula

time = frame / fps

At 60 fps, frame 60 is evaluated at 1 second. Each requested frame gets a predictable timestamp, even if rendering takes longer than real time.

30-SECOND EXAMPLE

How many frames?

frameCount = duration * fps
30 * 60 = 1800 frames
frames: 0 ... 1799

The output is 30 seconds long. The wrap frame is not written as an extra duplicate of frame zero.

04 / EXPORT

Make a verified render.

Use the settings in order; large dimensions and high frame rates increase the amount of work dramatically.

01

Choose a manageable test

Start with 1080p, 30 or 60 fps, and a short duration. Confirm the motion looks right before raising the output size.

02

Set the duration and background

Choose a duration such as 10 or 30 seconds. Transparent backgrounds are useful for image sequences; the checkerboard is preview UI, not part of the rendered pixels.

03

Analyse, then test

Use Analyse job to check the configuration, then Test render to catch errors without waiting for a full job.

04

Render and inspect

Choose an output format that the current browser reports as available. When complete, check the verification status and download the resulting file.

The live workspace probes the selected resolution, frame rate, and codec before offering a render path. Do not assume every device supports every combination; trust the capability status shown in Diagnostics.
05 / SEAMLESS LOOPS

Make the motion periodic.

Enabling the Loop setting tells TRILYVA the intended cycle length. It does not automatically make arbitrary animation loop. Use periodic functions so the last rendered moment joins the first cleanly.

// A repeating angle: the same value returns after one cycle.
const angle = motion.loopProgress * TAU;
const x = width * 0.5 + Math.cos(angle) * width * 0.2;
const y = height * 0.5 + Math.sin(angle) * height * 0.1;
01

Set the loop duration

Enable Loop and choose the same cycle duration as your intended composition.

02

Use circular motion

Use sine/cosine or another periodic expression. Avoid motion that only grows, such as x += 1, unless it is wrapped back around deliberately.

03

Analyse the seam

Press Analyse seam. A mismatch means the first and wrap frames differ; revise the animation until the seam test matches at the sampled resolution.

06 / QUICK FIXES

When something breaks.

SYMPTOMCHECK THIS FIRST
Preview is blankRead the compile/runtime message, check braces and quotes, then press Run again.
Preview and export differAvoid Math.random(), Date.now(), and variables that accumulate across frames. Use seeded random() and derive values from the current frame/time.
Loop seam mismatchesCheck every animated value for periodicity. An enabled Loop checkbox alone does not create a loop.
MP4 is unavailableOpen Diagnostics. Try a lower resolution/frame rate or use an output format the browser confirms is supported.
Transparent video looks opaqueThis pipeline does not write an alpha plane to MP4/WebM. Use a PNG sequence for transparent output.
Large render is slowThat is not automatically a failure. Test a short section first, keep the tab visible, and check available storage and memory.
