TRILYVA / THE COMPLETE TUTORIAL

From first frame
to final export.

A full practical guide to using TRILYVA: understand the workspace, write a working animation, shape the motion, choose a composition, test the browser's capabilities, render, export, and diagnose common problems. It also covers full-library folder/ZIP batches and saving a chosen frame as PNG, JPG, SVG, or EPS.

This is a complete written tutorial, not a fixed 60-second animation or promo. Follow it at your own pace; there is no time limit. Duration, frame rate, resolution, and output format are choices for your project and depend on the options available in the running browser.

02 / FIRST ANIMATION

Make something move.

Start with one simple shape. Once this works, build up with text, paths, layers, gradients, and more complicated timing.

01

Open the renderer

Launch the workspace. Locate the animation source editor and the Run/preview action. If a previous project is loaded, copy its code somewhere safe before replacing it.

02

Paste this starter

It clears the frame, computes a position from the current time, then draws a white circle.

window.renderFrame = function (time, frame, fps, ctx, width, height) {
  ctx.fillStyle = "#050505";
  ctx.fillRect(0, 0, width, height);

  const travel = Math.cos(time * 2) * width * 0.22;
  const x = width * 0.5 + travel;
  const y = height * 0.5;

  ctx.beginPath();
  ctx.arc(x, y, Math.min(width, height) * 0.045, 0, Math.PI * 2);
  ctx.fillStyle = "#ffffff";
  ctx.fill();
};
03

Run the code

Use the workspace's Run/compile control. If the interface documents a keyboard shortcut, you can use it too. The exact starter should produce a white circle on a dark background.

04

Play and scrub

Play the preview to feel the motion, then drag the timeline or inspect individual frames. The circle should move left and right and return smoothly because cosine is periodic.

05

Change one value at a time

Change the radius, travel distance, or time * 2 speed. Re-run and compare. Small isolated changes make it easier to learn what each parameter controls.

03 / UNDERSTAND THE CODE

What the function receives.

ARGUMENTMEANINGUSE IT FOR
timeTime in seconds for the requested frame.Motion curves, fades, timed scene changes.
frameThe current frame index.Frame-accurate logic, frame-based patterns.
fpsFrames per second selected for the job.Converting frame counts into time.
ctxThe Canvas 2D drawing context supplied by the renderer.Drawing paths, shapes, text, gradients and images already available to the project.
width / heightThe active render dimensions.Scale layouts to the chosen output rather than hardcoding one screen size.
TIMEBASE

Time from frame index

time = frame / fps

At 30 fps, 30 frames represent one second. At 60 fps, 60 frames represent one second. If the renderer evaluates frame 300 at 30 fps, the timestamp is 10 seconds.

DETERMINISM

Always derive the frame

const x = centerX + Math.sin(time) * radius;

Prefer calculations from the current frame/time. Avoid incrementing a shared position each call: rendering can request frames out of playback order.

Do not create a second canvas or run your own requestAnimationFrame() loop inside renderFrame(). The renderer owns the frame clock and supplies the drawing context.
04 / BUILD BETTER MOTION

Compose, animate, refine.

A good animation has a visual hierarchy. Begin with the main action, then add supporting detail only when it improves the idea.

01 / EASING

Make movement feel intentional

function easeOut(t) {
  t = Math.max(0, Math.min(1, t));
  return 1 - Math.pow(1 - t, 3);
}

Use eased progress for entrances and exits. Linear movement is useful for technical motion; eased movement often feels more natural for typography and objects.

02 / TIMING

Build a scene from progress

const start = 2;       // seconds
const length = 1.25;   // seconds
const p = Math.max(0, Math.min(
  1, (time - start) / length
));

Keep scene start and duration explicit. Clamp progress so an entrance reaches its final state and stays there.

03 / LAYERS

Draw back to front

Draw background first, then large forms, then typography and fine details. Canvas uses the order you issue drawing calls, so foreground elements should usually be drawn last.

04 / TYPE

Design for the frame

Keep key text away from the edges, use a small number of type sizes, and verify legibility at the final output size. Do not rely on a tiny preview to judge fine details.

05 / COLOUR

Use colour with purpose

Use consistent background, foreground, and accent colours. If the render needs transparency, do not paint an opaque background rectangle over the canvas.

06 / PERFORMANCE

Measure before adding detail

Many gradients, huge text effects, and thousands of particles can make each frame expensive. Test a short sequence before increasing resolution, duration, or complexity.

05 / COMPOSITION

Choose settings for the delivery.

01

Set the aspect ratio

Choose a frame shape that matches the destination. For a standard widescreen video, use 16:9 when that option is available. Recheck typography after changing dimensions.

02

Pick resolution

Use a smaller size for look-development and debugging. Move to the delivery resolution only after the composition is approved. Larger images increase memory use and render time substantially.

03

Pick frame rate and duration

Choose them based on the intended motion and destination—not because one example used a particular length. Frame count is duration multiplied by FPS; many workflows use frames numbered from zero through frameCount minus one.

04

Choose the background

Use a solid background for a finished composition. Use transparent output only when the selected export path supports it; transparency in the preview alone does not guarantee transparency in a video file.

High resolution and high frame rate combinations can be very demanding. TRILYVA's actual diagnostics and enabled settings take priority over any general example in this guide.
06 / PREVIEW AND INSPECT

Find problems before rendering.

PLAYBACK

Judge the rhythm

Watch the full sequence at least once. Look for abrupt changes, unreadable text, overlapping elements, and transitions that start too early or finish too late.

SCRUBBING

Inspect specific moments

Scrub to the beginning and end of each scene. If a problem appears only between two moments, inspect the frames around that transition. Press F12 to open the in-app DOCS panel when the browser lets the page receive that key; otherwise click the DOCS tab or the Docs · F12 toolbar button.

FRAME CHECK

Look at exact frames

For flicker or jitter, compare adjacent frames. Verify that positions are calculated from time/frame, and avoid unseeded randomness or mutable state.

DEVICE CHECK

Preview is not export speed

The preview can prioritise responsiveness and may not run at the requested output frame rate. Use a test render to validate the actual export path.

07 / RENDER AND EXPORT

Use a safe render sequence.

Do not begin with the biggest possible job. Validate the idea, validate the settings, then render the complete output.

01

Save or copy your source

Keep a known-good copy of the animation before changing the composition or attempting a large render.

02

Analyse the job

Use the available analysis/diagnostics controls to check the selected dimensions, frame rate, duration, and browser-supported output path.

03

Run a short test render

Render a short duration or test range if the workspace provides it. Confirm that the result plays, has the correct framing, and contains the intended background.

04

Render the complete job

Keep the tab open and avoid closing the workspace while it is processing. Large jobs can take a long time and require significant memory or storage.

05

Inspect the output

Play the exported file or inspect the downloaded image sequence. Check the beginning, middle, and end, and confirm the dimensions and duration before delivery.

06

Save a still frame

In the workspace Render panel, choose a frame index and select PNG, JPG, SVG, or EPS. Frame indices start at zero; the default is frame 0 and PNG. After a successful standard render, the selected still formats are exported automatically. Change the frame index to save another moment.

07

Render a full library

Choose Render Full Library, select a built-in or imported library, then choose Save to Folder or Save as ZIP. Set the still formats and frame index first. The output includes each animation’s MP4, selected stills, and metadata; video encoder availability and vector-operation support still depend on the current browser and renderer.

08 / SEAMLESS LOOPS

Make the ending meet the beginning.

A loop setting describes the intended cycle; it cannot make arbitrary movement seamless by itself. Use periodic functions and avoid one-way accumulation.

const TAU = Math.PI * 2;
const cycleSeconds = 4;
const phase = (time % cycleSeconds) / cycleSeconds;
const angle = phase * TAU;

const x = width * 0.5 + Math.cos(angle) * width * 0.2;
const y = height * 0.5 + Math.sin(angle) * height * 0.1;
01

Choose one cycle duration

Use the same intended duration in the composition and the motion math.

02

Loop every moving element

Check position, rotation, scale, opacity, particles, text, and background—not just the main object.

03

Test the seam

Use the workspace's seam analysis if available and inspect the first and last displayed frames. The final encoded frame is before the exact wrap time, so design transitions accordingly.

09 / QUALITY CHECK

Preflight your animation.

  • The first frame looks intentional and doesn't flash unexpectedly.
  • Text is readable at the final dimensions and stays inside safe margins.
  • Motion values come from the current time/frame rather than accumulated state.
  • Random elements use a stable seed or deterministic formula.
  • Scene transitions have no accidental gaps, jumps, or single-frame flashes.
  • Background and alpha behaviour match the selected output format.
  • A short test render has been checked before the full job.
  • The exported file opens and the duration, dimensions, and frame rate are correct.
  • The first and last moments have been inspected if the animation is intended to loop.

11 / TROUBLESHOOTING

Diagnose the actual failure.

SYMPTOMWHAT TO CHECK
Blank previewRead the compile/runtime message; check braces, quotes, variable names, and whether the function is assigned to window.renderFrame as expected.
Animation jumps or flickersDerive each frame from time/frame. Avoid Math.random(), Date.now(), or positions that accumulate on every call.
Preview and export differCheck whether the preview uses a lower resolution or responsive playback. Confirm the render settings and run a short export test.
Codec or format unavailableTrust the current capability/diagnostics result. Try a supported alternative or reduce the dimensions/frame rate.
Transparent output looks solidConfirm that the selected format preserves alpha. Use a transparent image sequence if the video path does not support it.
Render is slowReduce resolution for tests, simplify expensive drawing, shorten the test range, and check available memory/storage.
Downloaded file is missing or incompleteWait for the renderer's completion status, check browser download permissions/storage, and retry with a small test job.
Loop doesn't join cleanlyCheck every animated property at the seam; a loop toggle does not automatically make non-periodic movement repeat.
12 / REPEATABLE WORKFLOW

From idea to delivery.

01

Design a still frame

Decide what the viewer should notice first. Establish the background, focal element, and typography before adding motion.

02

Animate one property

Move, scale, rotate, or fade the focal element. Check that it works throughout the timeline.

03

Add scenes and transitions

Use explicit time windows and reusable drawing helpers. Keep source organised so later changes remain manageable.

04

Preview and diagnose

Scrub through transitions, inspect exact frames, and remove flicker or unintended jumps.

05

Test, render, verify

Use a manageable test export first, then the final settings. Inspect the resulting file before sharing or editing it further.
