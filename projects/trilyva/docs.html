01 / GET STARTED

Open, edit, preview, render.

Open the workspace in a current browser, select an example or library animation, and edit its JavaScript source in the ANIMATION SOURCE area. The preview is for checking composition and motion. For delivery, configure the composition and use the renderer's export controls.

Start with a short, low-resolution test. High frame rates, large canvases, complex drawing, and high target bitrates can substantially increase memory use, processing time, and output size.
02 / ANIMATION FUNCTION

Make the frame a function of time.

The renderer's animation contract is window.renderFrame(time, frame, fps, ctx, width, height). Keep the drawing logic deterministic: the same inputs should produce the same frame. Derive motion from time, not from a mutable per-frame increment.

window.renderFrame = function (time, frame, fps, ctx, width, height) { ctx.fillStyle = '#000'; ctx.fillRect(0, 0, width, height); const x = width * 0.5 + Math.cos(time * 2) * 200; ctx.fillStyle = '#fff'; ctx.beginPath(); ctx.arc(x, height * 0.5, 40, 0, Math.PI * 2); ctx.fill(); };

This is a small working reference, not a finished visual. The render system provides the Canvas context and dimensions. Avoid timers, DOM manipulation, requestAnimationFrame, network dependencies, and random values that change independently between frames.

03 / EDITOR AND SYNTAX COLOURS

Read code faster with colour groups.

The editor uses syntax highlighting to distinguish common JavaScript structures. Colour is only an aid for scanning; it does not validate the program or guarantee that the source will run.

LANGUAGE STRUCTURE

Keywords

Control words and declarations use purple, helping separate statements such as const, function, and return from drawing operations.

VALUES

Strings Numbers

Strings use orange, while numeric constants use pale green. Comments are green and are ignored by JavaScript execution.

CALLABLES

Functions

Recognised function names use yellow. Use descriptive helper functions to keep complex scenes organised.

RENDER API

Canvas/API Properties

Recognised renderer and browser APIs use cyan, properties use light blue, and selected literals use blue. The editor is a lightweight highlighter, not a full language server.

04 / SAVE SOURCE AND PROJECTS

Choose the file that fits the job.

The Save button inside the ANIMATION SOURCE toolbar opens a format picker. It is intentionally different from the main project Save action.

PROJECT PACKAGE

.tmotion

Exports the current TRILYVA project package, including the animation source together with composition and project settings. Use this when you want to preserve the project setup for later import.

PORTABLE SOURCE

.js

Exports only the current JavaScript animation source. Use it to edit the source elsewhere, archive the code, or share the animation function without the rest of the project configuration.

Other source actions

  • Copy copies the current animation source to the clipboard.
  • The main application Save stores a local project in the browser's project storage. It is not the same as downloading a source file; use the toolbar's format picker when you need a file.
  • Keep a backup of important work outside the browser. Browser storage can be cleared, unavailable in some privacy modes, or limited by the device.
05 / DOWNLOAD FROM LIBRARY

Export source files separately from rendered media.

The Library tab includes a DOWNLOAD FROM LIBRARY area. These actions download animation source code; they are different from rendering a library into videos and still images.

SINGLE FILE

DOWNLOAD JS

Select a built-in or local library and download one JavaScript animation as a .js file.

COLLECTION

DOWNLOAD LIBRARY (.ZIP)

Select a library to download its JavaScript files in a ZIP archive. The archive includes library-manifest.json and README.txt, and preserves source paths where available.

Imported libraries

A local library may come from supported JavaScript imports or an imported folder/ZIP, depending on the current Library controls. The selection dialog chooses which library to package; it does not execute a remote library or upload your files to a server.

Use DOWNLOAD LIBRARY (.ZIP) for source backups. Use the renderer's full-library render action when your goal is to export video or still-frame media for each animation. These are separate workflows.
06 / RENDER MODEL

Preview responsiveness is not export timing.

The requested frame time is calculated from the frame index and frame rate:

time = frame / fps

The live preview may become less responsive at demanding settings. The export process requests frames against the selected timeline rather than treating the preview as a real-time screen recording. Rendering every requested frame still does not mean every codec, resolution, or device combination is guaranteed to succeed; the encoder and system must support the configuration.

PREVIEW

Interactive inspection

Use playback, scrubbing, and frame inspection to evaluate motion and composition. Preview speed can vary with the scene and hardware.

EXPORT

Configured output

Use a short test and check the resulting file. For important deliveries, verify duration, dimensions, frame rate, colour, transparency, and continuity after export.

07 / STILL-FRAME EXPORTS

Export an individual frame.

The still-frame controls expose supported formats in the current interface, including raster and vector options where available. Raster export can include PNG and JPG; the vector recorder can offer SVG and EPS for supported drawing operations. The actual options are determined by the renderer build and how the animation draws.

  • PNG is useful for raster images and can preserve transparency.
  • JPG is a raster format and does not preserve alpha transparency.
  • SVG / EPS are vector-oriented exports. Canvas operations that cannot be represented by the vector recorder may be omitted or reported as unsupported.

Frame indices start at zero in the standard frame-inspection workflow. Inspect the downloaded file before using it in a production pipeline, especially when the scene includes transparency, gradients, filters, or complex Canvas operations.

08 / CAPABILITY LIMITS

Settings are not device guarantees.

TRILYVA exposes high-end configuration targets, including up to 16K output resolution, 240 fps, and a target bitrate of up to 2,000 Mbps (2 Gbps). These are upper settings limits, not a guarantee that all combinations are supported or practical on a given machine. Available dimensions, frame rates, codecs, and file destinations depend on browser capabilities, hardware, system memory, and storage.

09 / TROUBLESHOOTING

Diagnose by reducing the job.

  • Source will not run: check the browser console or the renderer's status message; confirm the expected renderFrame function exists and the code parses.
  • Preview is slow: temporarily lower the preview resolution or complexity. Preview load is not the same as final-render completion.
  • Export is unavailable: choose a configuration supported by the current browser and device; do not rely only on the requested width or frame rate.
  • The downloaded file is unexpected: confirm whether you chose .tmotion, .js, a source-library ZIP, or rendered media. Each contains different material.
  • Library ZIP is incomplete: confirm the intended library was selected and inspect library-manifest.json and README.txt inside the archive.
  • A vector still differs: the vector recorder may not support every drawing operation. Try a supported raster format when visual fidelity is more important than editability.
