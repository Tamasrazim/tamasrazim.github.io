OPEN RENDERER → SOURCE ↗ V2 / WEBCodecs + LOCAL MUXERS
01 / RENDER MODEL

Every requested frame is explicit.

The export clock is derived from the frame index rather than realtime playback:

time = frame / fps

Preview playback and export are separate systems. Rendering can take longer on heavy compositions without silently dropping requested frames.

02 / MEDIA STACK

Encoder + container are separate layers.

WebCodecs provides browser/device encoder access. V2 uses local MP4/WebM muxers for the output paths implemented by the renderer.

VIDEOH.264 / AVC
VIDEOVP9 / VP8
CONTAINERMP4
CONTAINERWebM / Matroska
03 / CAPABILITY DETECTION

No imaginary codecs.

The app should probe the selected resolution, frame rate and codec against the current browser before enabling a render path. Unsupported combinations remain visibly unavailable instead of producing fake files.

04 / THIRD PARTY

Output is local and explicit.

V2 does not require a vendored media runtime. Encoder availability comes from the current browser/device, and the supported containers are written locally by the renderer.
