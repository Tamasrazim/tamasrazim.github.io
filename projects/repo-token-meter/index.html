Repo Token Meter.

I made Repo Token Meter for a quick repository check: what files are there, how large is the text, and how has the project changed?

It uses repository data and a generated manifest when one is available. The token number is an estimate based on file size, not the exact count a particular model tokenizer will produce.

REPOSITORY / SIZE / GROWTH

A quick read on a repository.

I use the numbers as a rough planning signal, not as a billing forecast or an exact token count.

01 / SYSTEMINVENTORY

See what is in the repo

Browse the detected files and sizes to get a feel for the shape of the project.

02 / SYSTEMESTIMATE

Get a rough token estimate

Use the estimate to compare files or revisions. Actual token counts depend on the content and the tokenizer.

03 / SYSTEMGROWTH

Check how it has grown

Where commit and manifest data is available, use it to see how the repository has changed over time.
