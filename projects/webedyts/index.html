01 / PRODUCT

Open a site. Make the change. Keep the files.

The workflow I'm aiming for is straightforward: open a local HTML file or site folder, select an element, make a supported change, preview it, then export a copy. It won't push changes to a live website behind your back.

01 / IMPORTIN SOURCE

Bring a website into the workspace

Open a single HTML document or a local folder of pages and assets. Switch among imported HTML pages and inspect the project in the contained preview.

02 / EDITIN SOURCE

Change common visual properties

Select elements and adjust supported text, dimensions, position, spacing, display, borders, typography, color, and alignment without typing the corresponding style declarations.

03 / EXPORTEARLY WORKFLOW

Keep the files editable

Export a single HTML document or a website ZIP that preserves project-relative paths for files included in the import. Exported sites still need testing in their intended browser and hosting environment.

02 / SCOPE

What works now—and what doesn't yet.

Here's what the current editor source can do and what still needs proper testing. I'll keep the missing parts visible rather than dress them up as features.

IN EDITOR SOURCE01

Visual editing and history

  • Selection and common element property controls.
  • Duplicate/delete for supported selections.
  • Session undo/redo for supported edits.
  • Starter components, fifteen animation presets, and hover/focus thumbnails that preview the selected motion before applying it, with a visible keyboard-focus outline.
IN EDITOR SOURCE02

Local media and export

  • Local website folder and HTML import.
  • Media insertion for supported image, SVG, GIF, video, audio, and font uses.
  • Single-document and website ZIP export paths.
  • SHA-256 generation for build package files.
NOT COMPLETE03

Compatibility and release hardening

  • Framework, dynamic script, and server-route compatibility is incomplete.
  • Imported scripts remain disabled in the isolated preview.
  • 8K60 source integration does not guarantee smooth playback on all hardware.
  • Manual workflow verification and end-user installers remain outstanding.

04 / FAQ

Know the limits.

Practical answers about the current scope of WEBEDYTS.

Can it edit a live website directly?

No. The current workflow is based on local files the user is authorized to edit. A remote URL alone does not grant permission to rewrite a site's server files.

Will every framework and website work?

Not yet. Dynamic rendering, framework-specific paths, script-created resources, server routes, and back-end services are not comprehensively supported. The editor should report limitations instead of claiming universal compatibility.

Does 8K at 60 FPS mean every video plays smoothly?

No. Media integration aims to preserve supported source files up to that resolution and rate without silently transcoding them. Actual playback depends on codec support, browser runtime, graphics hardware, and memory.

What has to happen before release?

When I can reliably launch the app, import a project, edit it, export it and reopen the result on each supported OS. Then I'll publish the packages with platform notes, release notes and checksums.
