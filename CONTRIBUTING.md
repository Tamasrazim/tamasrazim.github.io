# Contribution Policy

This repository is maintained as a proprietary project by Robiul Rumman Razim
(Tamasrazim).

The source is available for inspection, but it is not an open-source contribution
project. Do not submit copied code, extracted libraries, repackaged versions, or
derivative work for redistribution.

Unless explicitly invited, pull requests and patches are not accepted as permission
to reuse repository code or assets. Any separately authorized collaboration must have
written terms covering ownership and licensing.

## Workflow for invited collaborators

1. Agree on the requested change and the files it may affect before starting.
2. Make a focused change on a separate branch; do not push directly to `main`.
3. Describe the actual changes, relevant tests, and any known limitations in the pull request.
4. Run the applicable project checks and review the final diff before merging.
5. Keep unrelated changes out of the pull request and preserve existing public routes and behavior unless the task specifically calls for changing them.

An invitation to collaborate applies only to the agreed scope. It does not grant general permission
to copy, redistribute, or reuse other source code or assets from this repository.

## Commit attribution

When two people have genuinely worked together on a commit, the commit may credit both authors
using Git's `Co-authored-by: Name <email>` trailer. Use the co-author's GitHub-associated email
and include the trailer only when that person made a real contribution to that commit.
Co-authorship records credit; it does not replace the written ownership and licensing terms above.

See `LICENSE` and `NOTICE.md` for the repository-wide rules.
