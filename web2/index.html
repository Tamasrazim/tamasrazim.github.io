03 / Working principles

A prototype proves a possibility. Testing proves what works.

I care about the part after the first successful run: how a tool handles real files, what happens at the edge of its limits, whether its output is valid, and whether another person can understand the workflow without guessing.

01

Build around a real task

Start from the problem and the person using the result. The interface should make the intended action clear.

02

Check the actual output

Preview, render, export and test are different stages. A polished screen is not evidence that the delivered file works.

03

Describe the limits

Separate implemented features, active experiments and future plans. Keep performance claims beside the tests that support them.
