TRILYVA is a procedural animation workspace built around explicit frame output. Write a renderer, inspect the motion, configure an export and work through each frame as a real unit of production.

TRILYVA / Frame studyTIME → FRAME → OUTPUT

01 / The model

One function. One frame.

TRILYVA uses a deterministic JavaScript rendering contract: window.renderFrame(time, frame, fps, ctx, width, height). The function receives the frame context and draws the requested image. That makes the source explicit and gives the renderer a consistent way to request frames.

Preview playback is useful for iteration, but it is not the same as a completed export. The export path is designed around sequential frame requests rather than skipping ahead to keep a preview smooth.

02 / The workflow

From source to deliverable.

Author

Write or paste a JavaScript frame renderer.

Inspect

Preview the animation and adjust the source before committing to a full render.

Configure

Set timing, dimensions and output options around the intended delivery.

Render

Generate frames in order, then assemble and verify the output.

03 / Boundaries

Deterministic, not generative.

TRILYVA does not include a built-in AI integration. It runs the JavaScript supplied to its renderer; any code produced elsewhere must be copied into the workspace manually. The output is determined by the renderer code and frame inputs, not by a generative model inside the application.

Rendering speed, memory use, browser limits and codec behavior still depend on the device and browser. Export settings must be checked against the actual file produced rather than treated as a promise based on configuration alone.
