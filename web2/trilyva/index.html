TRILYVA turns code into frame-driven motion. Write an animation, inspect it in the browser, configure an export and render the frames in sequence. The project is built around the idea that preview playback and final output are two different jobs.

01 / Rendering model

One function. One frame.

TRILYVA uses a deterministic JavaScript rendering contract: window.renderFrame(time, frame, fps, ctx, width, height). The renderer requests a specific frame, and the supplied function draws that frame into the provided canvas context.

The export path processes the requested sequence by frame index and checks the resulting sample count. Preview playback is for iteration; it can lag at demanding settings without determining the final export sequence. Verification checks frame-count consistency, not visual correctness of every animation.

Source

JavaScript renderer supplied or edited by the user.

Preview

Live canvas preview; performance depends on the complexity of the scene and the device.

Export

Sequential frame rendering followed by browser-supported media encoding.

02 / Output constraints

Settings with real limits.

The current settings include output targets up to 16K resolution, 240 frames per second and 800 Mbps. These are configuration ceilings, not a guarantee that every browser, codec, device or profile can encode every combination.

Bitrate target

20 Mbps minimum and 25 Mbps default. CBR is requested, but measured average bitrate may vary with scene complexity and the browser’s encoder implementation. Simple scenes can measure lower; TRILYVA reports the measured rate rather than failing a valid render on bitrate alone.

H.264 reference

800 Mbps is the H.264 Level 6.2 reference maximum. Profile constraints and browser/device support may impose lower limits.

File size

Each MP4/WebM output is capped at 2,000,000,000 bytes. Jobs projected to exceed the cap are blocked rather than silently reducing resolution, frame rate or quality.

Encoding

H.264/AVC and VP8/VP9 options are offered where the browser reports support. Actual output depends on the available media APIs.

03 / More than video

A wider creative workflow.

Library batch

Choose a built-in or imported JavaScript library and package each item’s video, selected still frames and metadata into a folder or ZIP.

Still-frame formats

The frame inspector lists PNG, JPEG, WebP, AVIF, BMP, TIFF, GIF, ICO, TGA, QOI, SVG, EPS, PPM, PGM, PBM, PAM, XBM and XPM. Some formats depend on browser encoder support; SVG/EPS inspector exports contain raster image data.

Offline Voice Studio

A formant-synthesis voice tool for timed dialogue, procedural soundscapes, PCM WAV output and subtitle cues. The voice is synthetic rather than a neural voice clone.

Local Movie Finalizer

Combines a video or stock clip with a browser-decodable audio file. It captures and re-encodes in real time, so it is not a lossless muxer.

04 / Boundaries

Deterministic, not generative.

TRILYVA has no built-in AI integration. It executes the JavaScript supplied to its renderer; code produced elsewhere must be copied into the workspace manually. The output is determined by the renderer function and its frame inputs, not by a generative model inside the application.

The browser remains part of the runtime. Memory availability, file-system pickers, codecs and media encoders vary between browsers and devices. The project is designed around those APIs rather than promising identical behavior on every platform.
